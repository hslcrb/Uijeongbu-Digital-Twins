# 2026-11-17 정적 충돌 사전 계산

## 사용자 발상과 문제 정의
사용자가 제안한 “정적 지형 충돌은 미리 만들어두고 움직임만 계산”을 적용했다. 기존 LocalCollisionWorld는 움직임마다 지형 자체를 바꾸지는 않았지만, 수평2.5m/수직1.5m 이동 시 주변 렌더 삼각형의 월드변환·선별·Octree 제작을 반복했다. 대합실 동선 측정에서 대부분 시간이 이 정적 인덱스 재구축에 쓰였다.

## 사전 계산 결과
실제 최종 v18 GLB를 Blender import한 뒤 재질 이름을 보존하여 Draco 없이 재수출했다. 숨김 원본까지 포함한 .blend 전체 export는 사용하지 않았다.
- 원본 해시: `377ef61ea364259524a43e0e744a57aabcfc8e661c60bfe86ac8b710ba3304d0`
- 변환된 세계 좌표 기준 삼각형2,425,623개에서 충돌용844,091개로 감소.
- 잎/풀, 낱개 자갈, 레일 체결구, 발광 창문 카드와 글자 등375개 장식 메시를 충돌에서 제외. 시각 모델은 변경하지 않음.
- 나무껍질, 실제 바닥/벽/계단/유리/고정 가구는 보존. 내부 공간을 임의로 생성하거나 막힌 벽을 삭제하지 않음.
- 32m 수평 격자420타일. 각 타일의 BVH를 오프라인에서 만들고 이진 배열로 저장.
- 이진 타일 합계44,431,280 bytes. 배포 원본은 약12MB gzip archive를2파트로 보존. 렌더 모델 파일 변경 없음.
- 대합실 주변9타일 선로딩은 약4.12MB. 동시에3개만 다운로드, 메모리 캐시는 최대16타일. 실제 질의는 현재 몸체/이동 여유2m에 필요한 타일만 사용.

## 실행 중 계산
브라우저는 완성된 BVH 배열을 읽으며 인덱스를 다시 만들지 않는다. 캐릭터의120Hz 움직임·중력·캡슐 접촉·단차 검사만 수행한다. 타일 경계에 걸친 동일 삼각형은 전역ID로 중복 판정을 제거한다. 공간은 복층 전체 높이를 포함하므로 지하/지상/대합실을 단일 높이맵으로 뭉개지 않는다.

## 업데이트와 실패 안전성
빌드는 실제 최종 GLB의 SHA-256과 manifest를 대조한다. 모델 버전이 바뀌었는데 bake가 갱신되지 않으면 정적 충돌 자산을 배포에서 제외하고 기존 LocalCollisionWorld로 폴백한다. 브라우저에도 같은 모델 해시를 삽입하여 오래된 manifest가 새 모델에 쓰이지 않도록 한다.
압축 묶음·각 타일의 해시/길이·경로를 검사하고, 런타임에서도 타일 해시와 이진 구조를 확인한다. 네트워크 실패·미로딩·손상·버전 불일치는 기존 충돌 검사로 폴백한다. 바닥 충돌을 끈 채 이동시키지 않는다. 기존20,000면 안전 제한은 폴백에 그대로 남긴다.
코드 리뷰에서 발견한 잘못된 manifest 항목의 완료 Promise가 다운로드 대기열에 남는 버그는 실패 회귀를 먼저 확인하고 수정했다.

## 실제 모델 비교
`docs/validation/static-collision-v18.json`에 동일 모델/동선의 Node CPU 비교를 저장했다. 다운로드는 완료된 조건이다. 브라우저 FPS 또는 모든 기기의 속도를 주장하는 측정이 아니다.

| 동선 | 기존 CPU | 사전 계산 CPU | 정적 인덱스 재구축 |
|---|---:|---:|---:|
| 중앙통로6.7초 | 941.8ms | 143.7ms | 7회 → 0회 |
| 좌측3.1초 | 457.6ms | 117.9ms | 누적10회 → 0회 |
| 계단 방향3.4초 | 99.6ms | 35.6ms | 누적11회 → 0회 |

대합실 입장, 중앙통로18.5m, 좌측8.5m 이동 후 접지와 예상 도착점0.5m 오차 범위가 통과했다. 모든 측정 프레임이 baked 모드였고 런타임 인덱스 재구축은0회였다. 삼각형 순서 차이로 수cm의 수치 차이가 있으나 테스트 허용 범위 안이다.

## 검증과 한계
단위검사: 바닥/벽 접촉, 타일 경계와 중복 접촉 방지, 손상 이진자산, 네트워크 실패, 모델 해시 불일치, 잘못된 manifest 대기열 정리, 빌드 시 오래된 bake 제외. 기존 보행/대합실/철도/눈 테스트와 전체 빌드도 실행했다.
계단은 기존 OSM 외벽과 내부 추정 배치가 겹치는 문제가 그대로 남는다. 이번 변경은 계산 최적화이며 계단 연결 완성이나 실제 역사 전체 내부의 재현을 뜻하지 않는다. 외부 도시 스트리밍/별도 움직이는 철도 모델의 충돌도 추가하지 않았다. Chromium GPU 상호작용 검증은 환경 제약으로 아직 완료하지 못했다.

## 재생성
권장 단일 파이프라인:
`BLENDER=/path/to/blender node scripts/rebuild-static-collision.mjs final-model.glb web/collision`

최종 GLB를 임시 snapshot으로 복사 → 그 파일만 decode → bake → 실제 대합실 동선검증 → 압축/분할/해시기록한다. 다른 모델의 비압축 기하와 해시를 실수로 짝짓지 않기 위한 진입점이다. 하위 `bake-static-collision.mjs`는 전문용이며 직접 사용 시 두 입력의 대응을 호출자가 보장해야 한다.
현재 출시 자산은 위와 동일한 단계별 명령으로 생성·검증됐다. wrapper 자체는 이번에 추가되어 구문/도움말만 검사했으며 별도의 끝단 재생성 실행을 했다고 주장하지 않는다.
마지막에 전체 테스트와 `npm run build`의420타일/모델 해시 복원 결과를 확인한다.
