# 의정부 디지털 트윈: 2026-11-17 납품 상태와 검증 범위

## 현재 구현
- v18 누적 역사 모델을 복구한 뒤 v19 커튼월 프레임 깊이 개선: v13c 이후 하부 통로·남측 유리 띠·자전거 보관시설·동측 안내탑 수정 복구. 원본 사진 기반 추정 치수와 실측값을 구분한다.
- 단일 Three.js 세계: 의정부역·주변 도시 스트리밍·6개 OSM 철도 경로가 함께 존재한다. 패널은 시점/표시 대상만 바꾼다.
- 철도: 연천–인천, 광운대–신창, 광운대–서동탄, 영등포–광명 및 의정부경전철 양방향의 선택 경로. 모든 선로·서비스·분기기를 뜻하지 않는다.
- 전동차: 통근형 10량/VAL208 참고 2량 절차적 근사 형상, 객차별 곡선 추종. 노선별 최대10편성, 총60편성 이내.
- 보행: 캡슐 중력·벽 충돌·점프·계단 시험·달리기·시작점 복귀, 기존 대합실 직접 진입.
- 정적 충돌: 최종 모델 SHA-256와 동기화한 420개 타일, 타일별 사전 공간 인덱스. 필요 지역만 다운로드하고 손상/누락/버전 불일치는 기존 런타임 충돌로 폴백한다.
- 날씨: 맑음/눈 선택, 입자 수 상한과 지붕 차폐 검사.
- 대합실 전광판: 공통 가상 운행시각과 편성 수를 사용한 양방향 도착/정차 화면. 실제 철도 API가 아니다.

## 검증 방법
- 매 통합마다 전체 Node 테스트, JavaScript 문법, 정적 빌드를 다시 실행한다.
- GLB 헤더·크기·내장 이미지·외부 이미지 URI 및 배포 모델 해시를 검사한다.
- 대합실 입장 및 중앙/좌측 동선은 최종 Draco GLB를 다시 디코딩해 물리기하 시험한다.
- 공개 코드 파일을 다시 다운로드하여 로컬과 바이트 비교한다. Cloudflare가 해당 main 커밋을 성공적으로 빌드했는지도 별도로 검사한다.
- 검증 환경의 WebGL 제약으로 실제 브라우저 GPU 프레임률·조작감·모든 시각 이음새는 검증하지 못했다. Blender 렌더는 실제 모델/코드 기반 별도 프리뷰이며 앱 스크린샷이 아니다.

## 남은 문제 (완료로 표현하지 않음)
1. 대합실 계단 방향에서 기존 외부 OSM 건물 껍질과 내부 추정 배치가 겹친다. 전체 내부→계단→승강장 연결이 완성되지 않았다.
2. 지역 철도 고도·경사·기존 선로와의 접합은 근사다. 새 철도 승강장/광역 지면/움직이는 열차는 역사 정적 충돌 타일에 포함되지 않는다.
3. 실제 제조사 외형, 분기기·신호 연동, 열차 탑승/충돌, 정확한 정차 위치, 모든 서비스 시간표는 미구현이다.
4. 가상 전광판과 열차 운행을 실제 도착정보로 해석하면 안 된다.
5. 사진과 유사하게 개선했지만 실측 100% 복제나 전 구간 사실성은 달성하지 않았다.

## 복구와 배포 과정
- 로컬 Git push 인증 부재를 확인하여 연결 GitHub API의 blob/tree/commit/ref 경로로 게시했다. 파일 저장 승인 요청을 반복하지 않고 기존 사용자 지시 범위에서 실행했다.
- 큰 바이너리는 변경 없는 바이트를 Base64로 전송하고 Git blob 해시 및 최종 공개 콘텐츠 해시를 확인했다. gzip 원본을 build.mjs가 복원하므로 압축본 갱신이 배포의 기준이다.
- 모든 main 통합은 두 부모를 가진 no-ff 병합으로 기록했다. 원격 main을 재조회한 expected SHA 조건을 사용하여 다른 변경을 덮어쓰지 않는다.
- v18 공개 모델 검증: 15,681,948 bytes, SHA-256 `377ef61ea364259524a43e0e744a57aabcfc8e661c60bfe86ac8b710ba3304d0`.
- 정적 충돌 공개 manifest와 대합실 타일 해시, 단일세계 철도 모듈의 실제 공개 바이트를 확인했다. 후속 모델 변경은 충돌 bake도 새 모델 해시로 재생성해야 한다.

## 최종 통합: v19
- 한화 커튼월 기존 격자 앞면을 보존하고 프레임 뒷면 깊이60mm/모서리2mm를 추가했다. 수치는 시각 모델링 추정이다. 모든 커튼월을 교체하거나 실측한 것이 아니다.
- 최종 모델: 16,363,132 bytes, SHA-256 `ec4e0d5584dcb01375547c4d37adb2cfecfb467ee02657a3c3fc7e89d9321316`. 이미지13개 내장, 외부 이미지 URI 없음.
- 전광판을 app의 공통 열차 시각에 실제 연결했고, 현재 전체38개 자동 테스트가 통과한다. 새 모델에는 반드시 동일 SHA의 재생성 충돌 타일을 함께 배포한다.
- 이 기록의 후속 배포 커밋과 공개 파일 확인이 실제 서비스 반영의 근거다. 이후 별도 프로젝트 착수와 구분하여 위 남은 문제를 완료로 간주하지 않는다.

- 실제 OSM JSON의 경전철 태그 `uijeongbu`를 공통 판별기에 추가했다. 기존 테스트 별칭 `uline`만 보던 오류를 수정하여 실제 경전철 데이터도2량 VAL근사차량/7m근사고가로 표시한다. 실제데이터 회귀검증을 추가했다.

## 후속 통합: 별도 운전실 체험차
- 선택역의 청록색 1량 체험차에 문 열기→탑승→운전실 진입 및 가상 출발/제동/문 제어를 추가했다. 기존 모든 편성의 탑승 기능은 아니다.
- 정차/역 좌표 정렬/문 열림 조건을 검사하고 가까운 역의 단일 예시 스크린도어와 함께 열린다. 실제 전 역 스크린도어·신호·다른 열차와의 충돌은 구현하지 않았다.
- 통합 후 42개 자동 테스트와 빌드가 통과했고 v19 정적 충돌 420타일은 유지된다. 세계 기하·상태 전이·카메라 추종은 Node 시험이며 GPU 조작 검증은 아니다.
- 조작과 상세 제한은 [CAB_GAME.md](CAB_GAME.md)에 기록했다.

## 후속 갱신: 기존 운행 편성 직접 조작 (이전 별도 체험차 대체)
- 별도 청록색 차량을 제거하고 기존 운행 편성 첫 객차의 청록색 탑승 마커로 직접 조작 대상을 연결했다. 정차 편성에 접근하여 문→탑승→운전실로 진입한다.
- 편성 전체가 수동 거리값을 따르고 하차 시 자동 운행 시간 오프셋을 조정한다. 수동 편성은 예상 도착 목록에서 제외한다.
- 원본 일체형 차체 문이 실제 구멍으로 개방되는 것은 아니며, 단일 예시 스크린도어·일반화된 실내·카메라 전환 방식이다. 다른 편성과 충돌 방지는 없다.
- 44개 테스트/빌드 통과. 하차 시 운전실 UI 모드 해제와 선택 상태 초기화도 통합 검토에서 보강했다.

## 게임용 편성 간격 제어 검토
- 최초 원형 범위안은 실제6노선 정상0.05초 간격600초에서52/60편성이 정지하고, 1초 간격1800초에서60/60교착하여 배포하지 않았다.
- 객차별 캡슐 형태 좁은 판정으로 수정하고 4m 평행선 회귀를 통과했다. 자동편성 충돌 시 낮은 우선순위 편성을 일시 숨김/운행 보류했다가 재진입시키는 게임 규칙이다. 실제 철도 신호·폐색·제동 모델이 아니며 자동 열차가 일시 사라질 수 있다.
- 수정 후 실제6노선 1초 간격3600초: 최종 보류3/60, 정상0.05초 간격600초: 최종 보류5/60. 전 편성 교착 없음. 두 시험의 최대 보류27/60. Node 단일 step 평균1.19ms/0.82ms이며 브라우저 FPS가 아니다.
- 자동화50tests 및 빌드 통과. 재현: 프로젝트 루트에서 `node scripts/check-fleet-soak.mjs`. 수동 편성끼리 마주치면 정지하며 실제 복선·신호 설계는 여전히 별개다.
