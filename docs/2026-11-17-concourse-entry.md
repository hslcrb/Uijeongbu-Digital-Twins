# 대합실 직접 진입과 원본 검증 정정

## 확인된 모델
배포된 station.glb 안에 사진 기반 3층 대합실 연구 모델이 이미 존재한다. scripts/build_interior.py의 내부 구조와 append_interior.py의 offset (2,57,11)은 미터 실측이 아닌 사진/OSM 기반 추정이다. 새로 임의의 내부 방을 생성하지 않았다.

## 동작
`대합실 입장`은 원본 카메라 local (1,-12,1.75) + offset에서 유도한 Three.js feet (3,11.05,-45) 부근으로 이동한다. 실제 바닥을 아래 방향 레이로 확인하고 캡슐/머리 공간을 검사한 뒤에만 진입한다. 바닥 없음·낮은 천장·충돌 예산 초과는 명시적으로 거절한다. 중앙통로를 바라보며 WASD와 드래그로 이동한다.

## 실측 테스트와 구분
최초 과부하 실험은 원본 blend의 숨긴 수목까지 export하여 잘못된 비교 대상이었다. 이 오류를 정정하고 **실제로 배포된 GLB를 import → 비압축 export**하여 검사했다. 레이캐스트·물리 수치는 렌더/브라우저 검증을 대신하지 않는다.

실제 GLB 동선 시험:
- 입장점 접지 y 약11.007m
- 중앙통로18.5m 이동: (3.03,11.007,-63.53), 접지 유지
- 좌측8.5m 이동: (-5.49,11.007,-63.67), 접지 유지
- 동선 최대 충돌면17,900개 (예산20,000개 이내)
- Node에서6.7초 중앙통로 시뮬레이션 약1초; 브라우저 프레임률 주장 아님

## 남은 계단 연결 문제
계단 입구로 더 이동하면 외부 `OSM_building_1311394019`의 면이 z≈-67.286m에서 내부 추정 배치와 겹쳐 막힌다. 높이11.2/11.8/12.4/12.7m에서 동일 벽이 검출됐다. 실제 사진 근거 없이 벽을 뚫거나 충돌을 무시하지 않았다. 따라서 전체 역사 내부/출입구/플랫폼 연결을 완료했다고 주장하지 않는다. 향후 내외부 배치 정합과 사진 대조 후 실제 메시와 충돌을 함께 수정해야 한다.

## 통합
철도 노선 장면에서는 대합실 입장 버튼을 숨겨 의정부 모델의 보행 상태와 별도 철도 장면이 섞이지 않도록 했다.
