# 2026-11-17 보행 물리와 자유 시점

## 문제 정의
기존 WASD 조작은 카메라를 1.5m씩 순간 이동시키므로 벽/바닥/중력이 없었다. 궤도 카메라의 극각 제한(Math.PI × 0.49)은 하부 관찰도 차단했다.

## 적용
- 관찰 모드의 수직 궤도 범위를 Math.PI까지 개방. 우클릭 드래그 이동, 휠 확대, WASD 및 Q/E 이동 유지.
- `보행 시작` 후 실제 모델의 바닥을 클릭해 진입. 벽/급경사/몸이 끼는 위치는 거절.
- 1.78m 캡슐, 1.65m 눈높이, 120Hz 고정 스텝, 중력/접지/벽 슬라이딩, 0.32m 이하 단차 오르기, 점프, 달리기.
- 포인터 잠금 시점과 드래그 대체 조작. R 시작점 복귀, 깊은 추락 복귀, 보행 종료, 포커스/탭 변경 시 키 초기화.
- 실제 GLB 표면 충돌이며 임의의 내부 방을 만들어내지 않음. 전역 도시 스트리밍 타일은 보행 충돌에 포함하지 않음.

## 실패와 해결
전체 원본 장면(1,214,061 삼각형)을 한 Octree에 넣는 시험은 Node 2GB 힙 초과로 종료됐다. **후속 정정:** 이 첫 시험은 숨겨진 원본 수목까지 재수출해서 실제 배포 GLB와 달랐다. 그 수치를 배포 모델의 성능 측정으로 해석하면 안 된다. 브라우저에 이 방식을 출시하지 않고, 플레이어 주변의 삼각형만 지역 충돌 인덱스로 구성하도록 변경했다. 큰 지면 삼각형 때문에 인덱스 공간이 다시 커지지 않도록 분할 영역도 제한했다.

## 검증
물리 회귀: 중력 착지, 벽 관통 방지/슬라이딩, 점프 후 착지/공중 연속 점프 금지, 긴 프레임 제한/리셋, 계단 오르기. 지역 인덱스: 먼 물체 제외/넓은 바닥 유지/이동 후 재구축. 기존 도시 스트리밍 테스트와 빌드도 실행.
후속 검증은 실제 `station.glb`를 Blender에서 import한 뒤 Draco 없이 재수출해 수행했다. 원본 blend에서 직접 export하지 않았다. 실제 배포모델 역 중심은 지역 1,524면·인덱스 약191ms였으며, 대합실 보행 동선은 최대17,900면으로 현재20,000면 예산 안에서 진행됐다.
Chromium 시작은 환경의 socket() EPERM으로 실패했고 승인 경로 재시도에서도 같았다. 실제 브라우저 화면 조작 검증 완료라고 주장하지 않는다.

## 범위와 한계
역사 전체 내부가 실측·모델링됐다는 뜻이 아니다. 기존에 없는 내부 공간은 계속 미구현이다. 미세한 구조물이나 겹친 원본 면은 진행을 막을 수 있고 시작점을 바꾸거나 관찰 모드로 확인해야 한다. 물리 시스템은 캐릭터 이동용이며 차량/파괴/물체 강체 시뮬레이션은 아니다. 지역 인덱스를 재구축할 때 고밀도 영역에서 짧은 정지가 생길 수 있다.

## 통합 검증 및 밀집지 안전 제한
- 눈 효과와 보행은 하나의 delta/렌더 루프를 공유한다. 보행 중 카메라는 OrbitControls가 아닌 캡슐 컨트롤러가 갱신한다.
- 충돌은 구현된 메시만 사용하며 미구현 내부를 새로 생성하지 않는다. 지역 충돌 삼각형 20,000개 또는 검사 1,000,000개를 넘으면 안내 후 시작 거절/보행 종료한다. 복잡한 내부를 모두 걸을 수 있다는 뜻은 아니다.
- 담당자 실제 v13c 샘플 측정: 외부191면 지역 생성46ms, 내부 밀집181,291면 생성3.9초로 보호장치 필요성이 확인됐다.
- 통합 자동검증 9개(물리·지역 충돌·예산 제한·눈·도시 스트리밍), JS 문법 및 빌드 검증. 클라우드 브라우저 WebGL 미지원으로 실제 GPU 렌더·키 입력 체감은 별도 검증 필요.
